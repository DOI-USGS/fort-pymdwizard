## Decisions

### Branches and release
- `feature/ui-modernization` is a long-lived integration branch. Each phase gets its own branch (for example `feature/ui-theme-loader`), branched from it, with a merge request back into it. Users get the whole redesign at once when it merges into `main-v2.2`.
- Development happens on GitLab (code.usgs.gov). GitLab mirrors to GitHub automatically.
- Users receive updates from GitHub through Help → Check for Updates (`check_for_updates` and `update_from_github` in `pymdwizard/gui/MainWindow.py`, around line 2190). The updater merges `origin/<locally checked-out branch>`. Installed copies follow `main-v2.2`, so nothing reaches users until it merges there.
- The release is **v2.3.0**, shipped on `main-v2.2`. The branch keeps its name, because it identifies the installer environment generation rather than the app version. Renaming it would mean switching branches inside users' installations.
  - Optional later: when a new installer is built for another reason, check out a version-neutral branch such as `stable`.

### Environment and installer
- **No new Python packages.** Users only get `git merge`, with no package install step, so a missing import would stop the Wizard from starting. Every phase must run on the current `environment.yml` (PyQt5 5.15.11, Python 3.13). This avoids building a new installer.
- **Icons are committed SVGs, not QtAwesome.** They're rendered with QtSvg, which the installer environment already has (`QtSvg.pyd`, `qsvg.dll`). They're recolored at load time from theme tokens. Candidate icon sets: Lucide (ISC), Tabler (MIT), Material Symbols (Apache 2.0). Commit the license file with the icons.
- Future installers must be built from a `main-v2.2` checkout. The installer copies the local `.git` folder (`installer_compile_v2.2.1_user_install.iss`, line 49), so users follow whatever branch was checked out at build time. `release/v2.2.2` doesn't exist on GitHub, and the update check fails for a branch missing from GitHub.

### CI
- GitHub Actions on the mirror. GitLab has no group or instance runners (checked 2026-11-20).
- Run pytest on Windows and Linux hosted runners, building the environment from `environment.yml`, with `QT_QPA_PLATFORM=offscreen`. Cache the environment keyed on `environment.yml`.
- Keep it separate from the existing `build-macos-installer.yml` workflow, which already runs successfully on GitHub.

### Layout
- **Sidebar** entries map one to one to the current section tabs. There is **no "classic layout"** setting.
- Optional sections appear in the sidebar. The Advanced → Optional Sections menu entries stay.
- **Each section stays one scrolling page of cards.** A **jump bar** at the top scrolls to a card and doesn't hide or move content. This was option (b).
- **No "Overview" page.** The mockup's pill row and Overview page were new navigation levels, and they're dropped.
- **Identification is too long and may be split into two pages.** See open questions.

### Spec files
- Only `.kiro/specs/` and `.kiro/steering/` are committed. `.kiro/settings/` (which may hold MCP credentials) and `.kiro/hooks/` stay ignored.

## Phase order

Each item is a separate merge request into `feature/ui-modernization`. Infrastructure comes before visual changes. Every merge request keeps the existing tests passing and adds tests for new behavior.

0. **Preparation**
   - Record a baseline: run the full test suite on the branch and note tests that already fail.
   - Add the GitHub Actions workflow (Requirement 12).
   - Take baseline screenshots of each section with `widget.grab()`.
   - Diff a fresh pyuic5 regeneration of every `UI_*.py` against the committed files, to find hand edits. This step only reads files. The committed files were generated by pyuic 5.6.
1. **Prototype (throwaway, not merged).** A standalone script on `feature/ui-prototype` that builds the mockup with real widgets and dummy data. Use it to check rendering on Windows and macOS, settle colors and spacing, and show regular users.
2. **Settings migration (Requirement 3).** Move `QSettings` off `"USGS_" + __version__` before the version changes to 2.3.0. Otherwise every user's preferences reset on update.
3. **Styling infrastructure**
   - 3a: a `pymdwizard/gui/styles/` package (`tokens.py`, `light.qss`, `apply_theme`) and the Fusion style. Don't name it `theme`, because `pymdwizard/gui/theme.py` is already the keyword widget.
   - 3b: replace the `NORMAL_STYLE`/`FOCUS_STYLE` swap in `wiz_widget.py` with `:hover`/`:focus` rules, and apply the font through `QApplication.setFont()`.
   - 3c: validation highlighting through a `validation` dynamic property instead of `setStyleSheet` (`highlight_error`, `highlight_attr` and `highlight_tab` in `MainWindow.py`, plus `spdom.py`).
   - 3d: move the remaining hard-coded colors into tokens.
4. **`.ui` file cleanup**
   - 4a: a regeneration script, committed with regeneration only.
   - 4b: remove the Arial and MS Shell Dlg 2 font pins.
   - 4c: relax min/max sizes, one section per merge request.
5. **Sidebar navigation** (Requirement 5), plus the Identification split if one is decided (Requirement 6).
6. **Cards and jump bar,** one section per merge request. Order: Identification, Metadata Reference, Distribution, Data Quality, Spatial, Entity and Attribute.
7. **Validation experience:** inline messages, Problems panel, status bar (Requirements 8 and 10).
8. **Toolbar** with SVG icons (Requirement 9).
9. **Release:** set `__version__` to 2.3.0, update `CHANGES.txt` and `docs/usage/`, then merge into `main-v2.2` (Requirement 14).
10. **Later:** completeness ring, chips, Ctrl+K, dark mode (Requirement 15).

Process for each merge request: branch from `feature/ui-modernization`, add tests, run the full suite, take before and after screenshots (Windows, plus macOS for visual changes), update `CHANGES.txt`, and include screenshots in the merge request description.
